## Areas to grow into (not created yet)

- **patterns/** — reusable architecture and implementation approaches.
- **troubleshooting/** — reproducible faults and tested fixes.
- **principles/** — general engineering heuristics with clear scope.
- **stack/** — technology-specific notes, with versions and references.

Create these folders only when there is a real note to put in them.

## Retrieval strategy

1. Identify the question or technical area.
2. Find matching entries in this index.
3. Open just the relevant notes.
4. Check the review date, evidence and applicability.
5. Validate against the current code and official sources.

## Maintenance rules

- Add an index entry when adding a new knowledge note.
- Keep titles descriptive and links relative.
- Merge duplicative notes instead of multiplying similar files.
- Mark superseded notes as deprecated and point to replacements.
- Never treat a historical note as stronger evidence than current, tested project behavior.
